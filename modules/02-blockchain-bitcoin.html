Blockchain and Bitcoin

A blockchain is one way for multiple participants to maintain an ordered record without relying entirely on one record-keeper. Bitcoin uses cryptographic commitments, signatures, peer-to-peer networking, and proof of work to implement a public payment system.

1. A working model of blockchain

For this course, use the following working definition:

A blockchain is a replicated, append-oriented ledger whose participants use cryptography and a consensus protocol to agree on an ordered history.

“Replicated” means more than one participant holds or checks data. “Append-oriented” means new records are normally added rather than silently editing old ones. “Consensus” is the rule for deciding which valid history to accept. The word immutable is often used informally, but a more precise description is tamper-evident and costly to rewrite under stated assumptions.

  1. Transactions
    Participants request state changes.
  2. Validation
    Nodes check signatures and protocol rules.
  3. Blocks and ordering
    Accepted transactions are grouped and ordered.

Hash pointers connect blocks. A change to an old block changes its hash, so the next block’s stored pointer no longer matches. In proof-of-work systems, rewriting the old block also means rebuilding later work and competing with the honest network. The hash pointer detects a change; the consensus rule and economic work affect which history the network follows.

2. When is blockchain a reasonable choice?

Ask who writes the data and who trusts whom. A blockchain can help when several independent parties need to write to a shared history, no single operator is accepted as fully trusted, and participants need to verify the same rules. It may provide shared ordering and independent checks.

A conventional database is usually simpler when one organization is trusted to control updates, one operator can resolve disputes, or performance/privacy requirements matter more than distributed verification. A blockchain does not make incorrect input true; it can preserve a false statement faithfully.

Design testCould the parties use a normal database with a clear administrator and audit log? If yes, compare that simpler option before proposing a blockchain.

3. Double spending

Digital information can be copied. A payment system must stop the same value from being spent twice. In Bitcoin, a transaction refers to previous outputs as inputs. Once a valid transaction spends an output, another transaction attempting to spend that same output conflicts with it. But before the network settles on an ordered history, different nodes may see competing transactions or blocks.

Proof of work and chain selection help nodes converge on one history. If a conflicting transaction appears on a competing branch, a later reorganization can change which spend is in the main chain. This is why merchants often wait for confirmations rather than treating every newly seen transaction as final.

4. Proof of work: target, hash, nonce, difficulty

A miner assembles a candidate block header and searches for a header hash that satisfies the current target:

hash(block_header) ≤ target

Because a secure hash output is unpredictable, miners try different nonce values and hash again. If they exhaust the nonce range or need to change other header data, they can also change transaction choices or a coinbase extra-nonce field to produce new header inputs. Checking a proposed block is much cheaper than finding one: a node hashes the supplied header once and compares it with the target.

Target and difficulty move in opposite directions

  • A higher target accepts more possible hash values, so finding a valid result is easier.
  • A lower target accepts fewer hash values, so finding one is harder.
  • Difficulty describes how hard it is to meet the target relative to a reference target. Different materials may express the comparison using slightly different formulas; focus on the inverse relationship.
  • When target changes but hash rate stays the same, expected search time changes in the opposite direction. For example, roughly halving the target roughly halves the success chance per attempt.

The network adjusts difficulty over time so blocks are not found persistently too fast or too slowly as total mining power changes. A difficulty change does not alter the hash function; it changes the threshold a hash must meet.

5. Full nodes, light nodes, and mining

RoleMain workWhat to remember
Full nodeDownloads and independently checks blocks and transactions against the rules it implements.Validation and mining are different roles. A full node need not mine.
Light nodeDownloads less data and uses compact proofs and information supplied by peers.Lower resource use usually means relying on assumptions about peers or proof context.
MinerChooses transactions, constructs a candidate block, and searches for proof of work.A miner proposes; nodes still decide whether the block follows consensus rules.

The coinbase transaction is the special first transaction in a mined block. It claims the block subsidy allowed by the rules plus included transaction fees. Halving refers to scheduled reductions in the block subsidy. Fees are not the subsidy and need not halve with it.

6. UTXOs and a worked payment

Bitcoin does not store each wallet’s spendable amount as one account balance field. It tracks unspent transaction outputs (UTXOs). A transaction consumes earlier outputs as inputs and creates new outputs. Each output can be spent only once. The fee is the difference between total input value and total output value.

Example

Alice spends inputs worth 0.7 BTC and 0.5 BTC. She creates an output of 0.9 BTC for Bob and 0.299 BTC as change back to herself.

  1. Total inputs: 0.7 + 0.5 = 1.2 BTC.
  2. Total outputs: 0.9 + 0.299 = 1.199 BTC.
  3. Fee: 1.2 − 1.199 = 0.001 BTC.
  4. The two old UTXOs are consumed; the new Bob and change outputs are candidate UTXOs.

A transaction’s confirmations count the blocks built on top of the block that includes it, with conventions sometimes counting the containing block as the first confirmation. More confirmations usually mean more accumulated work would need to be replaced. Age or confirmation count increases confidence under the protocol’s assumptions; it does not make reversal mathematically impossible.

Quick check

If the target becomes lower, what happens to mining?

Mining becomes harder because fewer hash outputs meet the threshold. With hash rate held constant, expected time to find a valid block increases.

Does every full node mine?

No. A full node validates. Mining is an additional role that searches for proof of work.

Why is there a change output?

Bitcoin transactions spend whole UTXOs. If the chosen inputs exceed the payment plus fee, the remainder is returned in a new output instead of becoming an unnecessarily large fee.

Do more confirmations guarantee that a transaction can never be reversed?

No. They make a successful replacement increasingly costly under the honest-work assumptions, but the risk is probabilistic.

Exam-ready summary

  • Explain why a blockchain coordinates a shared ordered history.
  • State the double-spending problem in terms of one output being spent twice.
  • Relate target size to the probability of a valid hash.
  • Distinguish full validation from mining.
  • Balance UTXO inputs, outputs, and fee correctly.
  • Explain why confirmations reduce risk without creating absolute finality.
